Flag any of:

Error handling:
- Error assigned to _ or return value not checked
- Error propagated without adding context the caller lacks
- Panic used for a recoverable error
- Error variable shadowed in an inner scope

Nil and bounds safety:
- Nil pointer dereference without guard
- Slice/array index without bounds check
- Map lookup assuming the key exists
- Type assertion without comma-ok

Resource management:
- File, connection, or response body not closed
- Missing defer for cleanup
- defer inside a loop (defers accumulate until the function returns)
- Resource not released on an error path
- Long operation ignoring context cancellation
- Network operation without a timeout

Error type discipline:
- Lookup by ID returning (nil, nil) instead of a not-found error
- External errors (sql.ErrNoRows, os.ErrNotExist) escaping the implementation boundary untranslated
- Leaf error carrying both Code and Err. Leaf errors carry Code and Message, wrapping errors carry Op and Err.
- Missing Op wrap on a significant function boundary

SQL and data access:
- rows.Close() not deferred immediately after a successful QueryContext call
- Result slice declared with var (encodes as JSON null). Initialize with make([]*T, 0).
- rows.Err() not checked after the iteration loop
- Caller-supplied strings interpolated into a SQL ORDER BY or WHERE clause
