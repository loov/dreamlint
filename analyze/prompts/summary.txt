Field guidance:
- purpose: what the function does from the caller's perspective, not how. Do not restate the function name.
- behavior: edge cases, side effects, non-obvious return values, and error conditions. Do not repeat the happy path from purpose.
- invariants: observable contracts. Preconditions the caller must satisfy ("input must be non-empty"), postconditions guaranteed on success ("returned pointer is never nil"), and invariants that always hold. Empty array if none apply.
- security: whether inputs are validated or sanitized, whether authentication or authorization is enforced, whether sensitive data is handled, whether output is escaped. Empty array if nothing security-relevant applies.
